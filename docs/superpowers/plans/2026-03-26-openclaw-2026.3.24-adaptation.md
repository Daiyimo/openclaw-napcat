### Task 4: Implement `before_dispatch` hook

**Files:**
- Modify: `src/channel.ts`

This task adds the `hooks.beforeDispatch` field to `qqChannel`. The hook needs access to per-account state (rate limit map and config), so the implementation pattern uses a module-level `Map` keyed by `accountId` to store per-account state.

- [ ] **Step 1: Add the module-level inbound rate-limit store**

Near the top of `src/channel.ts`, after the `clients` Map declaration (around line 57–58):

}

```

```

- [ ] **Step 3: Clean up the store when `startAccount` exits**

In `gateway.startAccount`, in the cleanup block at the bottom (after `client.disconnect()`, roughly line 894–895), add:

```ts

```

- [ ] **Step 4: Add the `hooks` field to `qqChannel`**

After the closing `},` of the `messaging` block (at the very end of `qqChannel`, before the final `};`), add:

```ts
  hooks: {
    beforeDispatch(ctx: any) {
      const accountId: string = ctx.AccountId ?? ctx.accountId ?? "";
      const store = inboundStores.get(accountId);
      if (!store) return ctx; // account not started yet, pass through

      const config = store.config;

      // 1. 入站频控
      if (config.inboundRateLimitMs && config.inboundRateLimitMs > 0) {
        const key = `${accountId}:${ctx.From ?? ""}`;
        const now = Date.now();
        const last = store.lastTrigger.get(key) ?? 0;
        if (now - last < config.inboundRateLimitMs) {
          console.log(
            `[napcat-QQ][before_dispatch] rate limited: ${key} (${now - last}ms < ${config.inboundRateLimitMs}ms)`,
          );
          return null; // 拦截，不分发
        }
        store.lastTrigger.set(key, now);
      }

      // 2. 静默关键词过滤
      if (config.silentKeywords && config.silentKeywords.length > 0) {
        const body: string = ctx.Body ?? ctx.RawBody ?? "";
        for (const kw of config.silentKeywords) {
          if (body.includes(kw)) {
            console.log(
              `[napcat-QQ][before_dispatch] silent keyword matched: "${kw}", dropping message from ${ctx.From ?? "unknown"}`,
            );
            return null; // 拦截，不分发
          }
        }
      }

      // 3. 日志 trace
      console.log(
        `[napcat-QQ][before_dispatch] From=${ctx.From ?? ""} ChatType=${ctx.ChatType ?? ""} SessionKey=${ctx.SessionKey ?? ""} AccountId=${accountId}`,
      );

      return ctx; // 继续分发
    },
  },
```

### v1.6.0 - 适配 OpenClaw 2026.3.24 (2026-03-26)

#### 新增

**1. `describeMessageTool` 接口实现**

在 `messaging` 对象上实现 `describeMessageTool()`，让 OpenClaw Control UI 的 "Available Right Now" 区域能正确显示 QQ 频道的可用工具。QQ 所有消息均路由到 `chat` 工具，`hint` 传递消息类型（`direct` / `group` / `channel`）。

**2. `before_dispatch` Hook**

新增 `hooks.beforeDispatch`，在消息分发给 AI agent 之前触发，支持：

| 功能 | 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |

**3. 新增配置项**

| 配置项 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `inboundRateLimitMs` | number | `0` | 入站每用户频控间隔（ms） |
| `silentKeywords` | string[] | `[]` | 静默关键词列表 |

- 未使用已废弃的 `listActions` / `getCapabilities` / `getToolSchema`，无需迁移
