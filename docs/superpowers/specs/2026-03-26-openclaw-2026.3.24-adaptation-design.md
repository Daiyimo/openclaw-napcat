## 背景

`@openclaw/qq` 是一个 OpenClaw 插件，通过 OneBot v11 协议连接 QQ（使用 NapCat）。当前版本 v1.5.1 适配至 OpenClaw 2026.3.13。本次升级为预防性适配，目标是确保插件在 OpenClaw 2026.3.24 下正常运行，并接入三个新特性。

### 已有优势（无需迁移）

- 已使用 `openclaw/plugin-sdk/*` 子路径导入（不是旧的 `extension-api`）
- 未使用 `listActions` / `getCapabilities` / `getToolSchema` 等已废弃方法
- 未依赖 `CLAWDBOT_*` / `MOLTBOT_*` 环境变量
- 未使用 Chrome extension relay (`driver: "extension"`)

## 特性一：`describeMessageTool` 接口实现

### 背景

OpenClaw 2026.3.22 要求插件实现 `ChannelMessageActionAdapter.describeMessageTool(...)` 方法，替代已废弃的 `listActions` / `getCapabilities` / `getToolSchema`。该方法用于消息发现（message discovery），让网关知道当前消息应路由到哪个工具，并在 Control UI 的 "Available Right Now" 区域展示。

### 实现位置

`src/channel.ts` → `qqChannel.messaging` 对象上新增 `describeMessageTool` 方法。

### 实现逻辑

```ts
describeMessageTool(ctx: { message: any }) {
  // QQ 所有消息均路由到 chat 工具
  // hint 传递消息类型，供 Control UI 展示
  const chatType = ctx.message?.ChatType ?? "direct";
  return { toolName: "chat", hint: chatType };
}
```

返回 `null` 表示该消息不触发任何工具（可用于静默拦截场景，但此处统一返回 chat）。

### 类型声明更新

在 `openclaw-plugin-sdk.d.ts` 的 `messaging` 接口中新增：

```ts
describeMessageTool?: (ctx: { message: any }) => { toolName: string; hint?: string } | null;
```

## 特性二：`before_dispatch` Hook 注册

### 背景

OpenClaw 2026.3.22 新增 `before_dispatch` hook，在消息分发给 AI agent 之前触发，携带标准化的入站元数据（canonical inbound metadata）。插件可在此做预处理、拦截、或日志记录。

### 新增类型声明

在 `openclaw-plugin-sdk.d.ts` 中新增：

```ts
// BeforeDispatchHook: 返回 ctx 表示继续（可修改），返回 null 表示拦截
export type BeforeDispatchHook = (ctx: any) => Promise<any | null> | any | null;

// 在 ChannelPlugin 上新增 hooks 字段
interface ChannelPlugin<TAccount> {
  // ...已有字段...
  hooks?: {
    beforeDispatch?: BeforeDispatchHook;
  };
}
```

### 实现位置

`src/channel.ts` → `qqChannel.hooks.beforeDispatch`

### 实现逻辑

`before_dispatch` handler 执行以下三项：

**1. 入站频控（每用户）**

基于 `config.inboundRateLimitMs` 对同一用户/群聊做入站频控。使用 `Map<string, number>` 记录最后触发时间，不满足间隔则返回 `null` 拦截。

- 频控 key：`${accountId}:${ctx.From}`（区分账号和来源）
- 默认值：`0`（不限制）

**2. 静默关键词过滤**

若 `config.silentKeywords` 非空，检查 `ctx.Body` 是否包含任一静默关键词。命中则返回 `null` 拦截，不触发 AI 响应（也不发送任何回复，与 `keywordTriggers` 白名单逻辑正交）。

**3. 日志 trace**

打印标准化入站元数据（From、ChatType、SessionKey、AccountId），方便调试。

### 频控状态管理

入站频控 Map 在 `startAccount` 作用域内创建，随账号生命周期自动销毁，无需额外清理。

## 特性三：过渡退出回复（Routed Delivery）

### 背景

OpenClaw 2026.3.22 要求：由 hook 或插件内部触发的回复，应通过 normal final-delivery path 路由，以保留 TTS 和路由交付语义。

### 当前状态

`channel.ts` 的 `outbound.sendText` / `sendMedia` 已正确使用 `client` 直接发送，是标准的 outbound 路径，不受此影响。

此特性主要影响：**插件在 `before_dispatch` 返回 `null` 拦截后，若需要发送自定义回复（如"频率限制中，请稍后"）**，应通过 `runtime.channel.reply.routeReply()` 而非直接 `client.sendXxx`。

### 实现

在 `before_dispatch` hook 中，若拦截并需要通知用户（如入站频控命中），通过已有的 `client` 实例发送一次轻量提示（不走 AI agent，直接 client.sendXxx 即可，因为这是插件自身的回复，不需要 TTS 语义）。

> **注：** OpenClaw 的 routed delivery 语义主要针对 AI agent 产生的回复。插件内部的系统提示（如频控通知）直接用 client 发送是合理的，不需要走 routeReply。

## 新增配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `inboundRateLimitMs` | `number` | `0` | 每用户/群聊入站频控间隔（ms）。0 = 不限制。例如设为 `3000` 表示同一来源 3 秒内只触发一次 AI |
| `silentKeywords` | `string[]` | `[]` | 静默关键词列表。消息 body 含任一关键词时静默拦截，不触发 AI，也不回复 |

两项均为可选，不填则行为与 v1.5.1 完全一致（向后兼容）。
